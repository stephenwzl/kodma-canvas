更新日期 2026-11-18。版本 v0.2，设计稿已绘制，待评审。开发暂缓，I1 尚未启动。以前置 [S003 结项](../003-drafts-files-ui/spec.md)为基线，恢复开发需另行确认。

## 目标

用户打开一份本地稿件，在右侧「Kodma Agent」里用自然语言生成可编辑图层，或修改已选中的对象。用户可以使用 Kodma 提供的模型服务，也可以自行配置模型端点。两种模式使用同一个本地 Agent，画布结果能正常撤销、保存和重开。

## 首版范围

| 部分 | 首版交付 |
| --- | --- |
| 稿件内对话 | 「设计」与「Kodma Agent」共用现有固定右栏。支持发送、流式回复、停止和失败后重新发起。打开另一份稿件显示该稿件自己的对话和状态 |
| 画布工具 | 读取任务开始时的选区和有限页面上下文。修改选中对象的填充或文字。在空白页新建包含框架、文本和基础图形的可编辑卡片 |
| 模型设置 | 「Kodma 托管」与「自定义端点」两种模式，默认托管。自定义端点提供 Base URL、模型、API Key 和「测试连接」 |
| 本地保存 | Agent 提交进入当前 FigCraft 文档、渲染、撤销和保存链路。对话和运行记录在稿件打开期间保存在内存，同一稿件切页或切标签可继续查看。关稿结束任务，重开可看到已保存的画布修改 |

后续单列首页「开始创作」、快捷模板、跨重启的对话历史和任务恢复、正式账户与付费套餐、云稿和通过 MCP 加入稿件的外部 Agent。S004 继续暂停。

## 两种端点

| 模式 | 请求路径 | 配置与归属 |
| --- | --- | --- |
| Kodma 托管 | Mac → Kodma 的 Cloudflare Worker → 选定的上游模型 | Kodma 管理服务地址、默认模型和上游凭据。Worker 做鉴权、额度和流式转发。首轮真实验证用可单独撤销的受限测试凭据，正式账户、计费与凭据发放另行设计 |
| 自定义端点 | Mac → 用户配置的模型服务 | 配置保存在本机，API Key 存 macOS 钥匙串。支持 HTTPS 和本机回环 HTTP。需要认证时发送 API Key，兼容无需认证的本机服务 |

两条路径使用 OpenAI 兼容的 `POST /v1/chat/completions`，支持 SSE、增量工具调用和工具回执。自定义 Base URL 指到 API 根路径，例如 `https://example.com/v1`。测试连接用独立的无副作用工具调用验证鉴权、模型、流式工具参数和回执，测试内容独立于当前稿件。修改配置后可重测。Cloudflare 上游模型与测试凭据发放方式在 I3 验证时记录。

任务发出时锁定当前端点和模型。切换设置只影响后续任务。连接中断、鉴权或限额失败直接反馈当前端点，由用户决定是否切换。随推理请求发送当前对话可用上下文及完成任务所需的画布数据。切换端点后从新对话开始，旧端点的对话上下文留在本地视图，避免自动发送给新服务。API Key 仅通过已配置端点的鉴权头发送。日志和错误回显禁止包含凭据，排障日志默认仅记录端点模式、任务状态与错误类别。

## 执行架构

**选用 [Rust Pi](https://github.com/nktkt/pi/tree/0808c756fa1991940def7f0f9837464417149419) 的 `pi-agent` 和 `pi-ai`，编进 Kodma macOS Rust 宿主。** 初始验证基线固定为提交 `0808c756fa1991940def7f0f9837464417149419`，版本 1.2.0。两个库承担 Agent 循环、消息流、工具调用和模型协议。只依赖需要的库，不注册 CLI、shell、文件或通用命令工具。Agent 网络与对话运行在后台，画布访问交回现有运行时事件循环。

```text
AppKit Agent 右栏 → Kodma Rust 任务层 → Rust Pi → 当前模型端点
                         ↕
                  FigCraft 命令与事务
```

1. **任务目标**。发送时记录任务 ID、稿件运行时身份、页面、选区节点和端点配置。在原页面启动时没有选区的卡片生成绑定该页。切标签、切页或切换选区后，工具依然引用发送时的目标。每个稿件同一时刻运行一个任务。
2. **提交前校验**。Rust 按任务目标路由读写，限制工具和参数，检查任务是否仍有效、稿件是否可写、页面和节点是否仍存在。节点失效、稿件关闭或切换成另存副本后拒绝写入。对将被覆盖的属性检查是否已在等待期间被修改。异常回执使用明确原因。
3. **事务与回执**。首版每条消息允许提交一个画布修改批次，可包含多条命令，例如创建卡片及其子层。复用 `command.batch` 的回滚与单步撤销。按任务 ID 和批次标识处理重复回调。同一批次收到两次也只写一次。UI 按引擎提交回执确认结果。模型结束时未执行变更，可正常显示回答。已提交但最终回复断线时，保留画布修改，并在对话中显示实际提交状态。
4. **停止**。停止、关稿或退出后取消网络和剩余工具。停止与写入在宿主提交点按顺序处理，停止先到则后续请求不能写入。已提交修改仍可撤销。提交前失败允许用户重试，旧任务的迟到事件失效。提交后失败不自动重跑已有修改。
5. **显示与存储**。工具回执、画布和属性栏来自同一个 FigCraft 引擎。Agent 对话按稿件与端点隔离，既有本地保存负责持久化设计修改。

### 选型原型证据

在 Kodma `67772c53` 上用同一 macOS arm64 Release 配置做 A/B。基线 75,957,904 字节，接入 Rust Pi 后 78,395,712 字节，增加 2,437,808 字节（约 2.32 MiB，3.21%）。这个数字是主程序可执行文件增量。两次采用 Rust 1.98.1、Thin LTO 和相同部署目标。

原型沿用 Bun 探针的本机 OpenAI Chat Completions SSE 测试端点并增加写工具回合。Rust Pi 收到分段工具参数，读到真实 Kodma 工作区的选中按钮，将填充从 `#3576C9` 改为 `#6738EF`，引擎读回、渲染、撤销和重做均通过。原型用本机控制端口跨进程联调。正式实现的进程内工具桥接、真实模型、Worker 与原生交互需按下表验收。
