## 技术路线

保留完整 FigCraft 运行时，通过隐藏外围 UI 和调整画布可用区域接入 Kodma。优先保持后续跟进 FigCraft 升级的兼容性，减少长期维护的本地差异。

本文件原先提出抽取运行时、拆分画布及特殊编辑状态。用户在 2026-11-16 决定采用保留运行时的路线，原拆分方案已被替代。沿用文件路径以保持已有文档链接有效。

## 保留与适配

## 原生承载验证与后续边界

当前 [桌面入口](../../apps/figcraft/src/main.rs)由 eframe 管理窗口，[画布入口](../../crates/ui-egui/src/canvas.rs)依赖完整 FigApp。新路线保留这一依赖，不将它当成必须拆分的缺陷。

S001 已在当前固定 egui / eframe / winit 版本上验证内容视图与 AppKit 窗口配合。后续工作区适配仍需核对事件循环、GPU surface 或图层的所有权、视图尺寸和销毁顺序。隐藏控件和改变独立窗口大小只能证明仅画布显示，不能证明已完成原生嵌入；当前采用的同窗组合及 SwiftUI 承载边界仍按实现说明保留。

原生输入控件与画布之间需正确转交焦点，避免删除、粘贴等快捷键作用到错误目标。系统输入法须验证组合文本、取消、候选框位置及切焦点行为，不能以模拟文本输入替代实机检查。

窗口隐藏或画布不在前台时，原有命令、协作与异步调度仍应工作。恢复显示时核对文档与纹理归属；原生视图关闭、重建不能重复创建 Session、丢失编辑状态或应用过期结果。

## 实施与验收

按 S001 依次核对 UI 隐藏与布局、实现仅画布显示、验证原生承载、回归现有编辑与控制能力、检查生命周期和上游升级兼容性。实际进展见[迭代记录](../../spec/001-canvas-editor/progress.md)，内容视图所有权、同窗组合及 SwiftUI 承载边界见[实现说明](../../spec/001-canvas-editor/implementation.md)。

默认 FigCraft 编辑器保留作为行为对照。多稿件、协作、成员跟随、分享权限和 MCP 沿用原实现；完整工作区回归在后续接入时进行，不另设前置协作开发阶段。

若当前原生承载方式不可行，记录具体证据后调整宿主适配方案，不自动恢复为大规模编辑器拆分。必要桥接集中在 macOS 层，不全局放松安全检查、不顺便升级依赖、不破坏 WASM 构建。

## 上游升级维护

每项本地差异记录改动原因、上游位置、回归场景与升级核对点。优先使用已有显示和布局能力，局部扩展宿主策略，避免重排核心状态和运行流程。

S001 包含一次明确基线与目标提交的本地升级演练，记录合并冲突、适配修复和运行结果。少改动是降低维护成本的手段，兼容性需要实际验证；不承诺未来版本自动兼容。
