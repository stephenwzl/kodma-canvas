## 产品目标

用户用语言表达需求、查看结果、提出修改意见，由 Agent 操作画布。用户无需学习绘图、排版和连线，也无需亲自编辑画布。

第一阶段围绕“把产品想法变成可讨论的界面与流程”。更广泛的概念、业务流程和架构表达属于后续可扩展方向。用户以“AI 时代的 Figma+”描述定位，这不是界面文案。

## 两种 Agent 入口

| 用户 | 交流位置 | 画布操作 |
| --- | --- | --- |
| 已在使用 Agent 的专业用户 | 自己的 Agent | 通过本地 MCP 操作 Kodma |
| 新手及半专业用户 | App 内置 Agent | 购买 Agent 套餐后，在 App 内交流生成 |

内置 Agent 在稿件右侧交流。外部 Agent 作为协作成员加入，聊天与操作记录由其客户端维护。

## 已确认的交互

- 首页提供任务模板，帮助用户开始具体任务，不摆一排抽象功能。保留自由输入。
- 左侧稿件列表是已确认的入口。不要删除它来保留后来添加的“最近项目”卡片。
- 账户与云端服务归左侧导航；当前首页概念以「设置」收口，具体账户入口待细化。
- 开始对话后，Agent 面板收在右侧，主体为画布。无需先完成整段对话再进入画布。
- 沿用 FigCraft 顶部标签页，在首页和稿件之间切换。不要额外增加 App 标题、返回首页按钮或重复导航。
- 固定右栏属于稿件。成员弹层从头像堆展开；仅具备可用视口的其他成员可以被聚焦。
- 删除第三页的“历史”和“导出”。概念稿也已移除第四页对应入口。

## 账户与文件同步

- 已登录时优先保存到云端，免费账户提供 10 个稿件名额。
- 云端名额用满后，新稿自动保存在本地，用户可以继续创建。
- 未登录时，稿件仅保存在应用沙盒，需要时可以导出。未登录状态不额外增加侧栏导出按钮。
- 本地与云端是同一份文件的同步关系，所有稿件使用同一列表，不分“云端稿件”和“本机稿件”栏目。
- 免费稿件名额与付费 Agent 套餐是分别提出的规则；套餐是否包含更多同步名额尚未决定。

## 界面约束

> For ui design and user experience, avoid adding secondary description labels or text, let the ui controls explains its usage.

少即是多。控件和交互能表达的用途，不加说明、辅助标签或口号。业务规则不自动转成按钮、分类或状态提示。

修改时保留已确认的交互，优先删除未经确认的附加设计。删除元素后调整间距、对齐和布局，并检查相关页面的一致性。

## 四页概念稿

[早期概念稿参考](https://figma.oldiron.work/files/1061fa703c391f22b02f623c)。当前工作版本以文首记录的 `kodma` 协作文件及其「Kodma · 高保真 UI」页面为准。

| 画板 | 内容 |
| --- | --- |
| 01 首页 | 左侧字标、稿件与设置；主体包含手绘插画、自由输入和三个快捷入口 |
| 02 开始对话 | 空画布与固定右侧 Agent 对话 |
| 03 生成初稿与修改 | 画布中的流程和界面；右侧继续交流 |
| 04 外部 Agent | 右侧展示所选图层的设计属性；外部 Agent 出现在成员弹层 |

首页的“做一个 App”连接到 02，“画出来看看”连接到 03；首页的首个稿件入口可打开 03，工作区首页标签返回 01。当前标签不跳转到另一状态。其余模板、关闭标签、发送、账户和分享等仅为概念控件，尚未实现对应业务。

“做一个 App”“改进现有页面”“梳理业务流程”是当前候选模板。阅读记录 App、对话内容、Claude Code 名称和 3/10 额度都是展示用示例，不代表模板清单、业务流程、模型或实际账户状态已经定稿。

四页为静态可编辑概念稿，部分节点配置了原型跳转；不代表真实 Agent 执行、保存返回或云端同步已经验证。未登录侧栏对照仍需与后续首页改动保持一致。
