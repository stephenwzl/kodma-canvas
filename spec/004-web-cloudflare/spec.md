## 开发前确认门槛

用户已选择参考 tldraw 的职责分层：**文档状态使用 Durable Objects + 附属 SQLite，R2 只保存图片等大资源，复用 FigCraft 增量同步协议**。这次授权限于更新架构图与文档；须待用户明确确认更新后的图和 S004 v1.1，才开始 I1 的代码、技术样机、依赖或资源创建。当前不开发、不部署；确认后仍遵守 UI 优先。

## 产品决定

- **Web 优先，部署目标为 Cloudflare。macOS 暂停、优先级 P2，保留并计划后续恢复，不取消、不废弃。** 已结项 S001 / S002 保持结项；尚未开发的 macOS S003 暂停，恢复时另记日期与范围。
- 本规格从浏览器产品重新定义，不把 S003 的 AppKit、应用数据目录、系统保存对话框或系统废纸篓流程改名后搬过来。
- 用户明确：**Web 首版包含登录、云端保存、跨设备打开稿件**。只部署静态编辑器、只保存浏览器内存或仅支持下载，不算首版完成。
- **UI 优先**：先核对设计、完成浏览器中实际运行的高保真界面并由用户视觉确认，再集中保障登录、稿件与云端存储功能、测试。技术可行性检查和必需的构建 / 启动不代替 UI 交付。
- 保留完整 FigCraft 文档模型、命令、撤销、编辑工具、帧循环与浏览器渲染运行时，不抽取或重写画布引擎。
- Agent 暂缓，未来按**云端 MCP**接入同一稿件体系另立规格。首版不开发本地 Agent 产品入口、对话、模型套餐或远程 MCP 服务。

## UI 来源与浏览器适配

当前可追溯设计是文件 `e37912c2dd7d1294` 的「Kodma · 高保真 UI」及 Design System，历史来源见 [S002 设计记录](../002-native-workspace/design-reference.md)。**本轮已更新 live 架构页，但尚未重新逐项 live 核对高保真 UI**。I1 在 live 后读取当前节点、组件与 token，建立 Web 设计对照；缺失的登录、文件管理、冲突、离线及恢复状态先补设计，不让开发人员随意拼默认控件。

- 首页延续暖白底、原创字标 / 插画和已确认层级。编辑窗口延续首页 / 稿件标签、单稿页面 / 图层导航、工具条与固定设计栏，选框使用 `#6738EF`；名称、列表、属性和按钮状态来自真实数据。
- 1440 × 960 为基准 CSS 尺寸，核对 1200 级窄视口、浏览器 100% / 125% 缩放与不同 DPR；重新定义浏览器布局，不把 AppKit 逻辑点直接当物理像素。
- 不绘制 macOS 系统标题栏 / 红黄绿按钮。浏览器前进 / 后退、刷新、地址栏直达及页面焦点有各自行为，不能靠桌面标签逻辑猜测。
- 视觉方案采用 Web DOM / HTML / CSS 产品外壳，承载原 Rust/WASM 完整编辑器；Web 适配层负责状态与命令桥接。具体前端构建工具在 I1 记录，优先最少依赖，不为写规格安装框架或引入新资产。
- 利用宿主显示策略隐藏原外围面板并划定真实画布区域；不能只盖住仍接受输入的编辑器。通过同一运行时快照更新导航与属性，不维护第二套可编辑文档。
- 无选区、混合值、只读 / 不适用字段、长名、同名、长列表、加载失败、输入焦点与禁用态都需实际呈现。控件表达用途，不添加二级说明、重复标题或口号；必要错误与冲突决策清晰。
- 未接入的 Agent、模板生成、成员和分享区域按 I1 明确的隐藏 / 禁用布局交用户确认；不把“开始创作”伪接为空白新建，不展示模拟在线成员或假生成结果。

I2 提供同尺寸设计与**浏览器实际运行截图**对照、交互状态及差异清单，由用户确认后进入 I3。已有真实功能接线保留；UI 阶段只运行推进界面必需的构建 / 启动 / 视觉检查，不用功能测试数量代替视觉还原。

## 稿件、账户和保存规则

1. **身份分离**：账户用户 ID、持久稿件 ID、浏览器运行时文档 UID、页面 / 节点 ID 各有职责。稿件名称不是唯一键；同名稿、同 NodeId 和重开后的新 UID 不得串稿。
2. **云端权威**：登录后默认云端新建。成功持久化初始内容和稿件元信息后才显示云端创建完成；失败保留本地草稿和重试入口，不产生可打开的假云稿。所有列表 / 内容 / 改名 / 保存 / 删除 / 恢复 API 都由服务端按登录身份鉴权，不信任请求中的 owner 字段。
3. **免费名额**：沿用已记录的 10 份云稿规则；名额已满的新稿保留在浏览器本地，同一列表展示，不分“云端 / 本机”栏目。名额检查须原子化，不能由前端数行控制。沿用的方案为软删除后释放名额、恢复时重新校验；I1 核对并记录该恢复规则及登录后本地稿件的逐份上传交互，不自动搬空本地草稿。
4. **未登录与账号切换**：本地稿件使用 IndexedDB 等事务性持久存储；明确存储被清理后无法保证恢复，提供下载副本。登录后不得自动上传全部匿名稿件；显式上传成功才建立云端关联。退出不把上一账户云稿 / 私有离线副本暴露给下一账户；匿名稿与账户离线副本分域管理。
5. **增量保存确认**：适配层捕获稿件 ID、运行时 UID、编辑代次和原协议的 client / batch / sequence 身份。普通微调只发送涉及的变更；DO 事务记录变更、服务端序号及去重结果，在符合平台持久化 / 输出门语义后才发确认。浏览器只确认对应批次，之后的新修改仍待保存；事件已发出、内存更新或 SQLite 同步调用返回均不能单独冒充可靠保存。
6. **本地与离开页面**：IndexedDB 保留未确认增量与必要检查点；不为每次微调无条件序列化整稿。I1 明确合并、最大等待、本地检查点、批次上限、失败重试和手动保存语义，I3 实测。离开警告仅作辅助，不靠异步 beforeunload 上传保证保存。断网不得显示云端已保存。
7. **多设备与协议兼容**：复用 FigCraft 的变更表达、服务端校验 / 排序、批次去重、重连和可适用的冲突处理；协议 seq 是文档版本依据，不新建与它并行的整稿 revision CAS 算法。旧 base sequence 不一律视为整稿冲突；按原协议接受 / 重放 / 拒绝，不能在适配层悄悄丢弃未知字段或整稿覆盖其他设备修改。不可恢复的编辑保留本地副本并明确反馈；同字段的既有收敛行为单独记录、实测。
8. **跨设备与 DO 生命周期**：同一稳定稿件 ID 路由到同一文档 DO。A 收到确认的 seq 必须可在 B 读取或恢复；DO 内存仅为缓存，驱逐 / 休眠 / 重启后从 SQLite 检查点、后续日志和资源引用重建。切设备不承诺恢复 A 的内存撤销栈；本地稿不承诺跨设备可见。
9. **大资源与完整稿件**：R2 只存图片等大资源，文档内保存授权资源引用。先上传并校验资源成功，再由 DO 持久化对应引用；资源未就绪不确认完整保存。R2 成功而文档失败产生的候选对象可重试 / 延迟回收，不假设 DO SQLite、D1 和 R2 之间存在跨服务事务。
10. **导入 / 下载 / 删除**：导入为独立稿件，拆出并校验大资源后初始化文档 DO；无名额时保持本地。下载时由授权文档状态与所有必需资源组装标准完整 .figcraft，缺资源明确失败。软删除 / 恢复由 DO 生命周期与目录协调，取消 / 失败不假成功；恢复历史时同步核对资源。资源垃圾回收必须覆盖历史引用、恢复保留期与待提交上传，不直接因当前画布未引用就删除。
11. **恢复与边界**：文档检查点与增量日志保留在 DO SQLite；新检查点可靠提交后才清理已覆盖日志，避免无限重放。利用平台有界 PITR / 软删除 / 历史保留制定恢复方案；单 DO 的 PITR 不等于 D1 与 R2 一起回滚，不承诺零数据丢失。I1 明确保留窗口、清理顺序、协调恢复和报警，I5 实际恢复演练。
12. **异常与完整性**：损坏 / 不支持 / 超限文件、资源和协议消息明确失败，不变成假空稿；复杂填充、富文本、图片、层级、页面与变量经增量重放及格式往返保留。I1 分别核对 Worker / DO CPU、内存、消息、SQLite 行 / 容量、资源上传和解码限制，不套用原生 512 MB 导入上限作为云端承诺。

## 技术路线与 Cloudflare 部署

具体职责与提交流程见 [Web 架构](../../docs/kodma/web-architecture.md)。v1.1 选择 **Workers Static Assets + 同源 Worker + 每稿一个 Durable Object / 附属 SQLite + D1 元信息 + 私有 R2 大资源**。参考 tldraw 的公开职责分层，不引入其编辑器、同步算法、代码或资产；FigCraft 的原生 TCP / 文件系统服务不能原样部署 Worker，需适配平台 transport / storage。[tldraw 官方架构](https://tldraw.dev/docs/sync)

| 层 | 负责什么 | 边界 |
| --- | --- | --- |
| 浏览器 DOM + Rust/WASM | 产品 UI、完整 FigCraft 编辑运行时、原增量同步客户端、本地待确认记录 | 不重写文档模型 / 撤销栈；本地保存不冒充云端确认 |
| Worker | 登录会话、路由与授权、稿件目录 / 名额、受控资源接口，连接映射到文档 DO | 浏览器不能任意选择内部 DO 身份或访问其他用户资源 |
| 文档 Durable Object | 每稿一个逻辑权威，复用 FigCraft 同步核心，校验 / 排序 / 应用增量 / 重连 | 内存是缓存；不能只把成功消息广播出去而尚未持久化 |
| DO 附属 SQLite | 文档检查点、有序增量日志、服务端序号、去重结果、资源引用及生命周期 | 文档持久化真相；不逐次写整稿 BLOB，不内嵌大资源原始字节 |
| D1 | 用户 / 身份映射、目录、所有权索引、名额及必要生命周期投影 | 不存第二份编辑模型，不作为文档 seq 权威；普通位置微调不要求同步更新目录 |
| 私有 R2 | 仅图片等大资源，按内容标识存储、授权读取 | 不保存日常文档快照、文档日志或每次微调的 .figcraft；文档备份不能自行改放 R2 |

### FigCraft 兼容与资源外置

[原增量 diff](../../crates/collab/src/diff.rs)、[同步客户端](../../crates/collab/src/client.rs)、[消息定义](../../crates/collab/src/message.rs)与[持久化钩子](../../crates/collab-net/src/hub/backend.rs)是复用起点。确认后 I1 验证 Rust 同步核心如何进入 DO 的执行环境并保持原语义；不为采用 tldraw 分层就切换为 tldraw sync / Yjs 或重写 CRDT。

源码中的图片变更目前携带字节（[资源变更](../../crates/collab/src/change.rs)、[资源序列化](../../crates/collab/src/docprops.rs)），因此资源外置是明确开发项。Web 适配层需要有版本的外置资源表示、权限验证和加载 / 重放路径；存储检查点 / 日志剥离大资源字节，恢复时为原核心提供所需资源。不能直接把 URL 填入原图片字段，不能声称既有 wire 已原生支持 R2 引用；保持默认原生 / 参考 Web 行为与 .figcraft 交换兼容。I1 验证资源加载、内存与消息边界，失败不得退回到每次整稿上传。

### 参考能力与开发门槛

Cloudflare 提供 DO 的 SQLite 事务存储、持久化 / 输出门语义和有界 PITR；这些是平台基础，**不等于本应用已经适配或通过恢复验证**。[SQLite 与恢复 API](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)、[内存生命周期](https://developers.cloudflare.com/durable-objects/reference/in-memory-state/)

首版登录至少完成一个真实身份提供方的端到端登录 / 回调 / 登出 / 过期流程；身份提供方尚未选定。I1 先核对可用账户基础设施，确定 provider、会话方案和回调配置，不自行注册第三方服务或假设已有凭据。I2 可呈现登录 UI，但模拟登录不算 I3 通过。部署密钥只放服务端 secret，浏览器不持有 Cloudflare 管理令牌、R2 主密钥或可跨用户读写的凭据。

- 产物包含 HTML / CSS、生成的 WASM glue、带内容哈希的 `.wasm` 与合法字体 / 素材。浏览器执行的 WASM 是静态资源，不算作 Worker 内嵌执行模块。Workers Static Assets 当前单文件上限为 **25 MiB**；I1 测实际产物并留余量，不用 gzip 后大小冒充可上传原文件大小。[官方限制](https://developers.cloudflare.com/workers/platform/limits/)
- 优先沿用 Trunk / wasm-bindgen 与现有 Web 打包链，产品输出与参考编辑器输出分离；默认参考入口和原生构建保留。浏览器字体加载和中文可见性单独验证，不能依赖 macOS 本机字体必然存在。
- `/` 和 `/drafts/:id` 为产品路由；刷新 / 直达需正常引导登录和恢复稿件。`/api/*`、`/auth/*` 优先由 Worker 处理，缺失 JS / WASM / API 不能返回伪成功 HTML；配置显式路由而非盲目依赖 SPA fallback。[官方路由](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/)
- `.wasm` 的 MIME 为 `application/wasm`，哈希资源可长缓存，HTML 需重新验证；私有稿件和会话响应不得进入公开共享缓存。验证 HTTPS、压缩、旧 HTML / 新资源不混版、错误与重试。
- 本地 → 隔离测试环境 → 经授权生产环境逐步交付；分别记录 Cloudflare 项目、环境、bindings、迁移、代码 SHA、产物校验值和可访问地址。不得复用生产数据做测试；回滚应用版本不等于回滚数据库或恢复已删数据。
- 本轮接入 DO / WebSocket 作为文档增量同步基础；成员 / 分享产品 UI 与未来云端 MCP 仍另立规格，不声称 native-only figcraft-server 已原样兼容 Workers。
