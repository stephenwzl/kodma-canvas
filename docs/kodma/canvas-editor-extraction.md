# Kodma 画布编辑器抽取与 macOS 原生接入方案

日期：2026-11-13。状态：源码检查后的实施方案，尚未实现或运行验证。

本方案依据当前仓库的 FigCraft 代码基线 `7b34dbab007461d6befa2eb45ff8eb14f8328328`。后续产品资料提交未改变应用源码。文中建议的模块和接口是待实现的边界，不代表仓库已经提供这些 API。

## 1. 目标与范围

保留 FigCraft 的画布、画布内编辑交互和对应功能，用 SwiftUI / AppKit 实现 Kodma 的外围界面。用户以指导 Agent 为主要流程；这一产品选择不意味着删减底层手工编辑能力。

原生界面负责窗口、顶部标签页、首页、稿件列表、账户、设置和固定右侧稿件面板（设计属性、内部 Agent、成员与分享）。标签页沿用已经确认的 FigCraft 交互形式。原生化不自动引入额外控件、说明文字或入口。

本次仅提交方案。实施阶段不包含账户、云端同步、套餐计费，也不重写文档格式或画布渲染器。

## 2. 源码结论

引擎、渲染器和 UI 已分层，但画布编辑器尚未形成独立组件。

- [画布入口 canvas::show](../../crates/ui-egui/src/canvas.rs)接收整个 `FigApp`，读取文档、编辑状态、面板状态、平台服务和协作状态。
- [FigApp 与 UiState](../../crates/ui-egui/src/lib.rs)同时保存编辑状态和整个应用的界面状态。
- [外层帧循环](../../crates/ui-egui/src/app.rs)负责画布前后的命令处理、输入法、快捷键、菜单、异步任务和窗口事件。只调用 `canvas::show` 会遗漏这些工作。
- [Session::pointer](../../crates/engine/src/canvas/tools/pointer.rs)处理工具手势；[工具定义](../../crates/engine/src/canvas/tools.rs)包含移动、缩放、形状、文字、钢笔、连接线等。大量编辑逻辑可以原样复用。
- [渲染器](../../crates/render/src/lib.rs)使用 CPU / tiny-skia 产生像素；[画布渲染任务](../../crates/ui-egui/src/canvas/render_worker.rs)负责局部更新、后台渲染、粗预览与精细结果；egui 再绘制纹理、选区、手柄和其他覆盖内容。
- [桌面入口](../../apps/figcraft/src/main.rs)目前由 eframe 管理窗口。现有画布并不是一个可直接交给 SwiftUI 的 `NSView`。

抽取单位应包含画布显示、编辑状态、输入处理和调度。仅隐藏侧栏或复制渲染函数不足以保留编辑功能。

## 3. 保留、解耦与替换

| 部分 | 处理 | 边界 |
| --- | --- | --- |
| 文档、节点、布局、文字、组件与变量等模型 | 保留 | Rust 引擎继续作为文档的唯一写入方 |
| 命令、撤销重做、编辑事务 | 保留 | 原生操作、画布操作和 Agent 共用命令与事务体系 |
| 选择、移动、缩放、绘制、矢量和文字编辑 | 保留 | 复用工具逻辑及 egui 输入适配，补齐原生事件来源 |
| 渲染器、后台渲染、纹理缓存、覆盖层 | 保留 | 将刷新唤醒接到宿主；保留文档与页面身份校验 |
| 颜色、渐变、裁剪、效果编辑状态 | 解耦 | 从面板和临时 egui 控件状态中抽出编辑目标 |
| 原型连线、交互编辑与预览 | 解耦 | 从右侧栏选项和应用标签页中分离模式、参数与预览会话 |
| 右键菜单、画布内编辑控件 | 保留逻辑、解耦呈现 | 保留操作及状态，不把现有全 App 菜单直接搬入 |
| 文件、剪贴板、拖放、URL、字体等服务 | 适配 | 通过宿主服务接入 macOS |
| 协作、MCP、异步完成、恢复保存调度 | 解耦 | 持续运行，不绑定画布是否可见 |
| 首页、标签页、外围侧栏、账户、设置 | 原生实现 | Kodma 负责布局、导航及产品流程 |
| 上游版本提示、应用更新、窗口管理 | 不纳入画布组件 | 如需对应能力，由 Kodma 应用层负责 |

“不纳入画布组件”不等于删除引擎命令或原始源码。初期保留原 FigCraft 应用作为对照宿主，新增独立画布入口，避免一边拆分一边失去行为基线。

## 4. 已发现的外围依赖

### 4.1 输入、焦点和中文输入法

[canvas/input.rs](../../crates/ui-egui/src/canvas/input.rs)负责鼠标、缩放、平移和部分焦点转移；[shortcuts.rs](../../crates/ui-egui/src/shortcuts.rs)负责快捷键、文本输入和 IME 事件；[app/ime.rs](../../crates/ui-egui/src/app/ime.rs)参与每帧输入法状态提交。

当前代码通过 egui 判断是否有字段获得焦点。原生 Agent 输入框不会自动出现在这个判断中。宿主必须明确通知画布是否拥有键盘，并在焦点交接时提交或取消组合输入，避免画布删除键误删节点、粘贴同时作用于聊天框和画布、切换稿件后把中文提交到另一份文档。

保留原有每批事件只应用一次、每帧 IME 状态观察等约束。系统输入法需要完整的文本输入客户端适配，包括组合文本、选区、候选框位置和取消行为，不能只转发字符。

### 4.2 右键菜单和命令入口

画布右击只设置 `app.ui.context_menu`，外层 [menus.rs](../../crates/ui-egui/src/menus.rs)才显示菜单并执行动作。该模块还处理粘贴、文件对话框，以及 Delete 在原型交互、页面、节点之间的不同含义。

抽取命令分发与可用性判断，区分编辑命令和宿主请求。原生菜单与 egui 菜单必须使用相同语义；不能绕过分发直接调用同名引擎命令，丢掉上下文行为。

### 4.3 渐变、裁剪和效果手柄

[canvas/handles.rs](../../crates/ui-egui/src/canvas/handles.rs)通过 `app.ui.picker`、`app.ui.crop`、渐变色标临时状态，以及属性面板的效果展开状态决定显示哪些手柄。

需要显式记录当前编辑对象、填充或效果索引、选中色标和编辑模式。控件打开、原生 UI 或 Agent 发起操作，都应能设置这些状态。关闭外围属性面板不能隐式取消仍在进行的画布编辑。

### 4.4 原型模式

[canvas/proto_canvas.rs](../../crates/ui-egui/src/canvas/proto_canvas.rs)根据 `RightTab::Prototype` 决定是否启用，并调用属性面板的交互编辑器。预览还经过应用层的 `present` 和标签页逻辑。

抽出画布模式、选中的交互、交互参数编辑和预览生命周期。模式不再依赖右侧当前展示什么内容；右侧 Agent 面板不影响原型连线能力。

### 4.5 工具、评论和覆盖界面

工具栏在外层帧循环里单独绘制；引擎保存当前工具。评论、标注操作也会发出 UI 请求。画布入口还直接绘制协作聊天、连接提示、版本预览提示和分支提示。

保留工具、评论标记、选区和必要编辑反馈；将要求界面介入的操作转换为宿主事件。区分画布上的编辑标记与应用面板。遵守现有固定侧栏、禁止悬浮面板的产品约束，不把上游浮层原样带入 Kodma。具体参数编辑控件的位置另行设计，本方案不增加入口。

### 4.6 平台服务与后台调度

现有 [Services](../../crates/ui-egui/src/services.rs)已覆盖文件选择、剪贴板、打开链接、Finder 定位、系统偏好等，可作为宿主服务接口的起点。

[app/commands.rs](../../crates/ui-egui/src/app/commands.rs)的 `background_tick` 处理控制请求、协作轮询、后台结果和保存相关任务。拆分时保留必要运行任务，将上游更新提示移出画布。窗口最小化或稿件标签不在前台时仍应处理 Agent 命令；隐藏状态可以延迟绘制，不能延迟命令生效。

## 5. 目标结构与状态归属

```text
SwiftUI / AppKit 应用
  ├─ 窗口、标签页、首页、稿件列表、固定稿件侧栏
  └─ NSViewRepresentable
       └─ 原生画布 NSView
            ├─ macOS 事件 / 焦点 / 显示适配
            └─ Rust 画布编辑器（egui）
                 ├─ 编辑状态、菜单调度、覆盖层
                 ├─ 渲染任务与缓存
                 └─ FigCraft Session / 文档 / 命令引擎

本地 MCP ── 控制请求队列 ── 同一 Rust 运行时
```

建议分出三个职责，具体 crate 名称在实施时确定：

1. 编辑运行时：拥有 Session、文档、命令队列、后台任务和变更通知。
2. egui 画布编辑器：拥有视图状态、输入处理、纹理和必要编辑控件，依赖运行时，不依赖原生应用导航。
3. macOS 桥接层：负责 Swift/Rust 接口、NSView 输入输出和平台服务。

运行时串行修改文档；渲染工作线程读取快照。Swift 只保存显示所需的状态快照和稳定标识，不维护第二套可编辑文档。多稿件命令显式指定文档 ID；渲染结果、异步导入和 IME 提交都校验所属文档，不能依赖“当前标签页”猜测目标。

选区、工具和编辑模式由 Rust 维护，Swift 通过通知更新相关原生控件。原生标签页负责展示与切换意图，文档的打开、关闭、未保存状态及异步任务由运行时确认。

## 6. 原生 UI 接入

### 显示与事件

由 AppKit 管理窗口和子视图，SwiftUI 通过 `NSViewRepresentable` 承载画布。优先保留 egui 的绘制输出和编辑逻辑，将其渲染到该子视图的 GPU surface。底层文档渲染仍使用现有 tiny-skia；不在抽取阶段改成另一套矢量渲染器。

现有 eframe 顶层窗口循环不作为嵌入接口。需要适配 egui 的输入、绘制输出和平台输出；具体 surface 创建、图层所有权、渲染器初始化及视图销毁顺序由原生嵌入验证确定。目前没有验证可直接把 winit 创建的内容视图搬进另一个窗口。

必须处理尺寸、Retina 比例、屏幕变化、鼠标捕获、触控板滚动与捏合、光标、IME、焦点和无障碍输出。原生侧栏改变宽度时，应保持拖动中的画布坐标连续。

仓库 [Cargo.toml](../../Cargo.toml)固定了定制 egui / winit 提交，其中包含输入法相关扩展。实施应以当前固定版本为准，不在桥接过程中顺便升级或替换为 crates.io 默认版本。

### Swift / Rust 接口

建议使用窄 C ABI 封装 Rust 运行时，Swift 只持有不透明句柄。第一版接口覆盖：

| 方向 | 内容 |
| --- | --- |
| Swift → Rust | 创建与销毁视图、绑定文档、提交命令、输入事件、焦点和尺寸变化 |
| Rust → Swift | 请求刷新、文档和选区变化、命令结果、错误、平台服务请求 |
| 宿主服务返回 | 对话框结果、剪贴板数据、异步文件读取完成等，携带原请求和文档标识 |

低频命令可以沿用命令 ID 与 JSON 参数；帧绘制和高频鼠标事件不通过 MCP 或逐帧 JSON 传图。GPU 资源留在渲染适配层内部。

接口必须约定缓冲区释放、回调线程、句柄失效和错误返回。AppKit 操作在主线程执行；异步回调不直接重入正在执行命令的运行时。SwiftUI 重建包装视图时，不能重复创建文档或丢失编辑会话。

### Agent 与控制通道

优先适配现有 [MCP attached backend](../../crates/mcp/src/backend.rs)和控制协议，使外部 Agent 操作正在显示的同一运行时，避免另外启动一个独立 headless Session。内置 Agent 也进入相同命令队列。

保留现有权限、命令结果和目标文档检查。涉及窗口的检查、截图或输入注入接口需要重新定义到原生宿主，不能继续返回旧 egui 窗口的数据。文档渲染与整窗截图是两种能力，分别验证。

## 7. 分步实施与验证

每步通过后再进入下一步。阶段验证产生的截图和测试稿仅用于本地检查，仓库继续只保存概念设计稿链接。

| 步骤 | 实施内容 | 通过条件 |
| --- | --- | --- |
| 1. 建立功能基线 | 列出工具、快捷键、菜单、UI 请求和平台服务；用合成文档记录现有行为 | 每项能力有对应入口、状态归属和验证方式；区分既有缺陷与抽取回归 |
| 2. 同宿主抽出画布入口 | 在现有 Rust / egui 宿主中分离编辑运行时和画布帧循环，移出首页、标签页、外围侧栏 | 无外围面板仍能编辑；主编辑回归通过，原 FigCraft 对照入口仍可运行 |
| 3. 解耦特殊编辑状态 | 处理渐变、裁剪、效果、原型、评论、菜单和工具状态 | 不依赖打开上游属性侧栏也能进入、操作、提交及退出这些编辑状态 |
| 4. 原生子视图验证 | 原生窗口承载真实 egui 画布；接入输入、显示、焦点和平台服务 | 中文、缩放、拖动跨边界、剪贴板和 Retina 显示通过；关闭和重建视图无崩溃或状态串扰 |
| 5. 命令与多稿件验证 | 原生标签页、Agent 输入框、MCP 接入同一运行时 | 指定文档修改正确；切换标签和后台执行不串稿；原生输入框不触发画布快捷键 |
| 6. 完整回归与接入确认 | 核对功能清单、性能、资源生命周期及原有构建 | 无未经确认的功能丢失；性能对比有记录；完成适用的仓库检查后再接产品页面 |

最小回归集：

- 选择、多选、框选、拖动、吸附、旋转、缩放、编组与撤销重做。
- 形状、钢笔、矢量点、文字编辑，中文连续组词、取消组合输入、选中文字替换。
- 渐变色标和手柄、图片裁剪、效果手柄、自动布局间距与内边距编辑。
- 组件实例相关操作、原型连线参数编辑与预览、评论标记和编辑入口。
- 右键菜单、复制粘贴文字/节点/图片、拖入图片和文档、文件对话框取消。
- 在拖动、IME 组合输入或异步导入期间切换稿件、改变侧栏宽度、关闭窗口。
- Agent 连续修改与人工手势交错时的顺序、撤销边界和渲染更新；不把一次手势与 Agent 操作意外合成一笔撤销。
- 最小化后 Agent 修改，恢复窗口时正确显示；断开连接、执行失败和超时如实返回。

功能清单以步骤 1 对实际命令和 UI 入口的盘点为准，上述清单不是删减范围。优先复用现有画布、IME、快捷键和渲染测试，再为拆分边界和原生事件适配补回归。涉及 AppKit 的行为必须实机检查，Rust 单测不能代替。

性能比较使用相同合成文档、窗口尺寸和显示比例，记录缩放/拖动响应、首帧与精细渲染延迟、CPU、内存及多次开关视图后的资源变化。不预先承诺帧率或工期。

## 8. 仍需验证的技术点

- 当前定制 egui 的绘制输出与原生子视图 surface 如何接合，以及资源释放顺序。
- 原生 IME 桥接是否完整保留现有上下文切换、重复事件抑制和候选框定位语义。
- 属性编辑、原型交互编辑中的临时状态是否还有未显式建模的依赖。
- 原生窗口与现有自动化检查、截图、输入注入及无障碍树如何对应。

以上影响实现细节，不改变“保留画布编辑能力、原生化外围界面”的边界。源码检查支持开展抽取，但不能替代步骤 4 的运行验证。
