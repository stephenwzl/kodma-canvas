# S001：Rust 宿主中的独立画布入口

日期：2026-11-16。状态：规格已编写，尚未实施。

## 目标

在现有 Rust / egui 宿主中提供一个可运行的独立画布入口。移除原 FigCraft 首页、标签页和外围侧栏的参与后，画布仍能完成基本编辑，处理外部命令并正确重绘。原 FigCraft 编辑器继续可运行，作为行为对照。

本阶段为后续 SwiftUI / AppKit 接入建立组件边界。完成标准同时包含结构解耦和运行行为；仅隐藏外围面板不算完成。实施与证据记录在[迭代进度](progress.md)。

## 范围

本阶段包含：

- 分离编辑运行时、画布帧循环及宿主职责，保留现有 Session、命令、撤销和渲染实现。
- 提供可重复启动的仅画布验证入口。可以是独立启动模式或薄验证宿主，最终方式在实施时记录；现有参考编辑器入口保持可用。
- 基本工具、鼠标与键盘输入、中文文字编辑、选区和视口、渲染任务与纹理更新。
- 现有 MCP attached backend / 控制通道接入同一运行时，保留权限、目标文档检查与错误语义。
- 将控制请求、协作轮询、异步完成及保存相关调度与外围 UI 的绘制解耦。
- 为拆分边界补必要的回归测试，以合成文档和本地截图验证行为。

后续阶段处理 SwiftUI / AppKit、C ABI、原生 NSView、原生产品页面，以及渐变、裁剪、效果、原型等特殊编辑状态的完整解耦。本阶段记录这些依赖并保持参考编辑器功能，不宣称仅画布入口已完成全部高级编辑能力。账户、云端名额、付费模型与套餐服务不在本规格内。

多稿件、协作、成员跟随、分享权限和 MCP 沿用 FigCraft 现有能力。针对本次触及的调度与文档边界做回归；双稿件、双客户端的完整产品验收在原生接入阶段完成，不作为开始抽取的前置项目。

## 组件边界

| 职责 | 持有或处理的内容 | 边界要求 |
| --- | --- | --- |
| 编辑运行时 | Session、文档、命令执行、撤销、后台队列与完成通知 | 文档保持唯一写入方；不依赖首页、标签条或属性侧栏是否绘制 |
| 画布编辑器 | 视口、输入适配、选区覆盖层、渲染任务与纹理 | 从调用方取得画布区域和焦点；不主动绘制应用导航或外围侧栏 |
| 宿主 | 窗口、事件循环、平台服务、刷新唤醒及外围界面 | 可选择参考编辑器或仅画布入口；共用编辑能力，避免维护两份编辑逻辑 |

接口与 crate 名称由实现确定并记入进度。允许分步迁移既有字段，但最终入口不能继续以完整 FigApp 或 UiState 作为隐式依赖，把外围状态整体搬入或用其包装类型透传也不算完成。特殊编辑状态的暂存依赖需明确列出并限制在对应适配边界，交给下一规格继续解耦。

所有用户可见的文档修改仍走已有命令体系。输入每批只处理一次，绘制不能重复提交命令。异步渲染结果校验所属文档与页面；关闭视图或更换目标后，旧结果不能覆盖新视图。

## 验收场景

所有场景均在仅画布入口执行，并对照同版本参考编辑器。工具可通过现有快捷键或命令选择，不为验证增加说明标签或产品功能面板。

| 编号 | 操作 | 预期结果与证据 |
| --- | --- | --- |
| AC01 | 分别启动参考编辑器与仅画布入口，打开同一合成稿件 | 两者均可运行；仅画布入口不绘制首页、标签条及外围侧栏；记录启动命令和截图 |
| AC02 | 用鼠标创建形状，点击选择、Shift 多选、框选、拖动、调整尺寸和旋转 | 文档几何与选区正确，覆盖层随编辑更新；记录行为检查及相关自动化结果 |
| AC03 | 创建文本，输入中文并连续组词，取消组合输入，选中文字替换；切出再切回焦点 | 无重复提交、丢字或未聚焦时误触发画布快捷键；中文输入使用 macOS 系统输入法实机验证 |
| AC04 | 依次创建、移动和修改对象，逐步撤销再重做 | 恢复到各步骤对应状态；一次手势不产生重复修改，外部命令不被误并入该手势 |
| AC05 | 平移、缩放、改变窗口尺寸，编辑后等待精细渲染；关闭并重新打开验证视图 | 视口与命中坐标一致，无旧纹理覆盖新内容、渲染线程异常或持续累积的任务；记录截图与资源观察 |
| AC06 | 经控制通道和 MCP attached 分别读取、创建、修改对象，再用鼠标继续编辑 | 操作落在可见画布的同一文档中，结果正确重绘、可撤销；非法命令与无效目标返回错误，文档不被错误修改 |
| AC07 | 不绘制画布时提交现有控制请求，并在恢复显示后核对；通过测试驱动协作轮询和异步完成 | 后台调度仍处理命令与已有协作事件，恢复显示后看到最新文档；记录调度测试及实机结果，分清应用主动隐藏与系统休眠 |
| AC08 | 运行参考编辑器的受影响回归与仓库质量检查，检查组件依赖 | 原入口未因抽取丢失行为，WASM 与分层约束保持；完整记录通过、失败和未执行项 |

AC07 的协作调度检查优先复用现有测试，不要求先新建完整协作产品。只读权限、独立成员和远端跟随的完整验证仍按原生接入计划执行。

## 实施顺序

| 迭代 | 工作 | 交付判据 |
| --- | --- | --- |
| I1 | 盘点本次涉及的帧循环、状态和平台服务，确定最小组件边界 | 有状态归属表、调用顺序与需保留的调度清单；只补必要基线，随后进入抽取 |
| I2 | 抽出运行时与画布入口，添加薄验证宿主或启动模式 | 编译可运行，AC01 通过；原入口继续共用编辑逻辑 |
| I3 | 接回输入、撤销、视口、渲染和平台服务 | AC02–AC05 通过；高级编辑遗留依赖已列明 |
| I4 | 接通现有控制队列和 MCP，验证隐藏时调度 | AC06–AC07 通过；无第二套 Session 或重复事件处理 |
| I5 | 核对结构边界、参考编辑器回归、截图与适用质量检查 | AC08 有完整结果；所有验收项有证据，迁移回归已修复，遗留范围明确 |

这些是同一开发阶段的实施顺序，不要求每个迭代都创建新的 crate，也不预先承诺工期。

## 验证与完成判定

优先复用已有输入、IME、渲染、控制通道与协作测试；新增测试覆盖抽取后独有的边界，例如无外围面板时可编辑、每批事件只执行一次、隐藏时继续处理命令、丢弃过期渲染结果。引擎单测不能替代画布交互与中文输入的实机检查。

同一合成稿件、窗口尺寸与显示比例下对比抽取前后的首帧、拖动缩放响应、CPU、内存及多次开关视图后的资源情况。记录测量方式和实际结果，显著退化需解释并处理，不用截图替代性能测量。

完成时提供：可运行入口及启动方式、状态与接口边界说明、AC01–AC08 的结果与对应版本、受影响测试与 `cargo xtask ci` 的实际结果、截图检查结论，以及交给后续规格的依赖清单。截图留在本地，仓库记录场景、版本与结论，不加入设计稿副本、私人数据或邀请凭据。

所有验收项通过后才标记完成。既有失败单独记录复现信息和影响；无法区分既有缺陷与迁移回归、质量检查未完成或存在未解决回归时，保留“待验证”状态，不写“CI 通过”。
