# 画布共创的 Grill 机制

适配自 grilling 的设计树与分轮澄清机制，以及 ask-matt 的入口路由。此文件是本草稿的执行规则；不要求额外安装外部 grill skill 才能使用基本访谈。

## 分轮澄清

1. 从当前材料和已确认要求建立本轮设计树：表达目标、受众、范围、关键对象与关系、需要比较或决定的事情。只展开影响当前任务的分支，不穷举整个产品。
2. 找出前提已经确定的未决问题。事实由 Agent 查材料、工具或项目取得；不能让用户回答本可查证的信息。证据仍缺失时保留未知，不把猜测包装成选择题。
3. 从当前可回答的问题中优先问最影响结果的一项，给推荐答案及简短理由，等待用户回答。用户要求集中讨论时可以合并彼此独立的问题；不能把依赖尚未回答的问题放在同轮。
4. 每轮回答后更新决定与依赖；用具体场景或反例检查含糊术语、边界、异常和取舍。用户否定推荐时沿其真实目标继续，不反复推回原方案。
5. 当本轮没有阻塞表达的未决问题时，简短复述拟表达的场景与关键决定，取得共识后进入绘制。用户已明确的要求和确认可以直接沿用；不为确认而重复确认。未决问题需要看图才可回答时，先确认探索目标，再画候选稿供讨论。

用户可以随时用画布回答：选中对象指出问题、调整位置、修改关系或直接改文字。读取这些变更并核对其含义，不要求把已经明确的视觉修改重新用文字解释一遍。视觉移动的业务含义不明确时才询问。

绘制后继续检查是否出现新分歧；只重开被影响的分支。画布不替用户做未授权的业务决定，也不以“已画出来”代表用户认可。

## 是否需要 grill-with-docs

- 普通表达、一次讨论或单次改稿：按以上机制工作，以当前对话和画布保留共识。存在工作目录本身，不构成创建文档的理由。
- 长期项目需要跨轮复用领域语言、用户明确要求持久化决定，或项目已有词汇表需要维护：读取 [grill-with-docs](grill-with-docs/SKILL.md)，按其入口组合 [grilling](grilling/SKILL.md) 与 [domain-modeling](domain-modeling/SKILL.md)。宿主支持调用时显式调用；否则读取并执行内置规则。
- 本草稿对该组合的适配：访谈轮次和本轮绘制范围遵循上文；仅处理当前目标的决定。事实调查默认自行完成，必要且获准时才委派，不强制 subagent。词汇表只在术语真正形成共识时更新；ADR 仅在难以逆转、缺少背景会令人疑惑且存在真实取舍时建议创建。
- 不为了画布共创额外生成长文说明、完整需求规格或工单。需要文字成果时按用户指定出口交付。
