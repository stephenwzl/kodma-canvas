# Kodma 稿件工作区架构草案

更新日期：2026-11-16。本文约定保留 FigCraft 完整运行时、接入 macOS 原生宿主时的状态归属与回归场景。状态归属是逻辑职责，不要求拆分现有 FigApp / UiState。四页设计是交互输入，宿主适配、账户与 Agent 接入的实现状态见[产品进度](README.md)。

## 状态归属

| 范围 | 所有者与生命周期 | 使用者 |
| --- | --- | --- |
| 窗口 | 宿主管理首页、打开的标签与当前稿件。关闭标签时解绑视图 | 顶部标签、左侧稿件列表 |
| 稿件 | 本地稳定稿件标识映射到已打开的引擎文档；云文件标识在同步成功后关联。重启后重新取得运行时标识 | 保存、打开、恢复、命令目标 |
| 画布 | Rust 持有可编辑文档。每个视图读取其稿件的页面、选择和视口 | 画布、设计属性、撤销 |
| 在线会话 | 每个已加入的稿件独立维护连接、访问能力、参与者与最近视口。重连后重新解析成员标识 | 头像堆、成员弹层、聚焦、分享 |
| 内部 Agent | 会话与任务关联稿件；草稿、消息与运行状态由任务层维护 | 右侧对话、生成和取消 |
| 外部 Agent | MCP 客户端持有对话和执行记录，加入对应稿件后以成员身份出现 | 同一成员列表与画布命令 |

右栏以稿件为输入。切换「设计」和「Kodma Agent」仅改变展示内容。切换稿件则重新订阅选区、任务和在线成员；带旧文档标识或旧订阅代次的回调丢弃。分享、聚焦以及从选区发起的修改在打开控件时捕获稿件目标，提交前再次验证目标仍有效。

## 命令如何落在同一份文档

1. 用户在「设计」面板选择的多个图层来自当前文档快照。提交属性时传入文档与节点标识，运行时检查存在性、编辑能力与字段类型。混合值保留到用户明确修改；一次修改对应一次撤销。
2. 内置 Agent 将一次可独立撤销的设计修改提交为命令批次。为每个任务记录目标稿件与批次标识；重试前对照已提交结果，避免重复创建。取消阻止后续批次，已经提交的批次仍可撤销。任务返回成功后才显示完成。
3. 外部 Agent 经已有 MCP backend 进入同一命令体系。本机 attached 模式需要额外传递客户端身份；仅共用宿主连接无法产生第二个可聚焦成员。首个协作验证优先让独立客户端加入相同线上文件，以其自身身份发布 presence。没有有效视口的成员仍显示在线，聚焦入口不可用。
4. 文档变更后，渲染与右栏从同一引擎状态刷新。非前台稿件仍处理协作与任务回执。宿主事件循环已有控制队列、协作轮询和自动保存入口。见 [MCP backend](../../crates/mcp/src/backend.rs)、[后台调度](../../crates/ui-egui/src/app/commands.rs)与[原生承载方案](canvas-editor-extraction.md)。

## 从一句指令到画布更新

FigCraft 的「Kodma · 技术架构」页用同一个例子对照两条链路：用户要求把按钮改成黑色。前两张拓扑图说明服务端与端的职责、桌面端各层的调用方向。后两张泳道图分别跟踪内置与外部 Agent。下表记录图中的提交位置与网络边界，供实现时核对。

| 接入方式 | 指令到提交 | 用户看到修改的时刻 |
| --- | --- | --- |
| 内置 Agent | 桌面端捕获稿件和节点，读取必要上下文。按云端推理草案，模型服务返回工具调用；用户端 Rust 引擎校验权限与目标，以可撤销批次提交。 | 本地提交触发画布和设计属性刷新。共享稿件随后上传变更，协作服务校验写权限、保存并广播。 |
| 外部 Agent，独立协作客户端 | 客户端加入共享稿件并取得快照。外部 Agent 通过 MCP 读取节点，按其配置调用模型，再通过 MCP 将修改提交到自己的稿件副本。 | 协作服务接受并广播变更，用户端合并、重绘后才显示黑色按钮。外部 Agent 的工具回执和对话记录留在其客户端。 |
| 外部 Agent，本机 attached MCP | 外部 Agent 指定稿件和节点，本机 MCP 将命令交给用户端同一个 Rust 引擎。 | 用户端本地提交后刷新。修改本地稿件无需经过协作服务；选择云模型时，推理仍需联网。 |

验证时分别观察工具调用、命令提交、共享同步和用户端重绘。模型返回后若节点已删除，应返回提交失败；本地已提交而上传失败，应保留修改并显示待同步。内置模型的供应与计量、断线后的同步恢复，以及本机 MCP 的独立成员身份仍待验证。

## 成员聚焦与分享

在连接进入 live 后从目标稿件读取成员快照。入口展示叠放头像，列表显示名字，以会话内的客户端标识定位成员；同名成员、同一人多个连接分别处理。选择可聚焦成员后对该稿件调用现有 `collab.follow`，根据远端页面和视口更新本地显示。Esc、手动导航、成员离开或切换稿件时结束跟随。聚焦只影响本地视图。上游已有头像点击、视口移动和退出的[行为测试](../../crates/ui-egui/src/live_tests.rs)。

分享按钮打开当前稿件的权限面板。提议先显式选择访问级别，再经现有 `collab.share` 创建或取得该级别的邀请；打开面板只读取状态。成功且目标仍一致时才允许复制链接。沿用服务端对本地与线上分享能力的区分，服务端校验实际写权限。邀请凭据仅传给明确的接收方，日志和仓库仅保留不含凭据的文件定位。权限策略及弹窗文案仍待定。见[现有分享行为测试](../../crates/engine/src/live_share_tests.rs)。

## 实施主线与迁移验收

先按 [S001 v2](../../spec/001-canvas-editor/spec.md)与[原生承载方案](canvas-editor-extraction.md)保留完整 FigCraft 运行时，隐藏外围 UI、适配画布区域并验证原生承载，再接入完整 Kodma 工作区。FigCraft 已有多稿件、撤销、协作、成员跟随、分享权限和 MCP 能力，本阶段复用这些实现，并验证宿主适配后仍能工作。必要的基线记录随适配进行，不先开展独立的协作功能开发或全面测试阶段。

开发顺序为：核对现有隐藏与布局能力，在原帧循环上实现显示策略，验证原生窗口承载及区域、焦点与生命周期，再接入原生导航和固定右栏。尽量不改动上游核心代码，通过适配差异审查与升级演练核对维护成本。每步运行相关回归，最终在完整工作区完成下表验收；适配回归在对应阶段修复，原有缺陷单独记录。此阶段不依赖付费模型或账户服务。

| 回归范围 | 原生宿主中的验收场景 |
| --- | --- |
| 稿件与撤销 | 在 A 打开属性编辑后切到 B，迟到的提交不能改写 B；撤销准确回到修改前 |
| 协作与成员视口 | 两个独立客户端同步同一稿件；第二个客户端仅加入 A，B 不出现该成员；跟随、退出与断线都能恢复手动导航 |
| 分享权限与 MCP | 查看邀请允许读取，修改被拒绝；编辑邀请通过 MCP 修改正确稿件；重连重试检查是否重复创建，记录原有行为与迁移差异 |
| 原生交互与后台调度 | 对照 02–04 验证标签切换、头像堆、聚焦和分享；输入法、撤销、MCP 命令与后台任务在切稿时正常 |

外部 Agent 的独立成员身份、任务重试与取消等新增语义，仍按前述边界分别确认和实施，不能因复用 MCP 与协作能力就记为已完成。

后续分别验证云端名额耗尽转本地保存、离线编辑重连和任务恢复。登录后本地稿件如何占用云名额、Agent 任务如何持久化，以及原生桥接的实现约束，均需在对应阶段确定。
