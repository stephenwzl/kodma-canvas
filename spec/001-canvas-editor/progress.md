## 真实鼠标拖动续作（2026-11-16）

基线 `7540a018`。先复现原生窗口拖动后对象仍在 `(120,100)`；清除首页状态、重新激活和新建宿主仍可复现。相同工具在默认编辑器能移动，但一次 120×80 物理像素的拖动有时只保留 30×20 文档单位，而不是 Retina 2× 下的 60×40。

临时只记录窗口指针事件，确认按下、移动、松开均送达。原 UI 每帧合并指针状态：按下和松开同帧时发送 Down / Up；已有拖动遇到移动和松开同帧时只发送 Up。引擎的 Up 提交已有预览，不为普通移动应用末次坐标，因而出现整次不移动或丢失末段位移。新增测试在修改前复现 `(120,100)` 原地不动，修复后通过。

修复局限于 `canvas/input.rs` 的释放处理：位置变化时先补发最后一次 Move，再发送 Up；位置相同的点击不补发移动。复用原引擎、事务与撤销，不改变宿主结构、轮询频率或完整运行时。临时指针日志已移除。回归覆盖默认 / 宿主两种模式、整次手势同帧 / 松开带最终位移两种批次，以及一次撤销 / 重做；运行复测脚本也加入单批次指针验证。

真实窗口验收结果：

- 原生宿主：桌面鼠标工具从 `(960,824)` 拖到 `(1080,904)`，文档对象由 `(120,100)` 变为 `(180,140)`；控制通道回读，一次撤销回到起点，重做回到终点。

### 实现与问题处理

- 验证宿主新增原生输入法下拉控件，通过 AppKit NSTextInputContext 列出当前可用的已启用输入源；只在明确选择时切换，其他时间反映系统当前源。列表最多 64 项，无新增依赖版本、资产或 unsafe。正常销毁时，若还能识别原输入源且当前仍是宿主最后选择，恢复原值；不覆盖外部后续选择。
- 真实切换中复现画布已失焦但旧 `ni` 预编辑仍显示。原生输入拥有键盘时，原输入围栏会跳过旧上下文的取消事件。新增回归先失败；现在只清除未提交的预编辑与缓存，保留文字编辑及光标。返回画布使用新的组词，丢弃帧不重复提交。
- 原生框曾在画布组词后接收到普通 `hao `。宿主现在等 eframe 关闭原画布 IME 后，在下一次宿主 tick 激活实际原生字段的文本上下文；仅字段正在编辑且窗口是 key window 时激活，不对滑块或后台窗口抢焦点。真实往返后原生框提交“好”，画布内容不变。该交接仍使用验证宿主现有的 100 ms 轮询，性能属于 AC08 后续测量范围。
- 另一次早期画布输入出现 `nihao `，重启后未稳定重现；之后记录到真实 Preedit / Commit 并完成往返测试。不把该早期观察归因为已经证明的引擎缺陷。临时输入事件追踪已从源码移除。
