# S003：稿件创建、文件管理与 UI 还原

更新日期：2026-11-17。修订：v1.2。优先级：**P2**。状态：**可独立进入 I1；开发与运行验收未开始**。

本规格只覆盖 macOS 原生工作区与本地文件。I1 从已验收的 S002 开始，不依赖 Web 登录、云端存储或部署。

## 目标与优先级

让用户在 Kodma 内可靠地创建、命名、找到、打开、管理和再次编辑自己的稿件，同时解决首页与编辑窗口相对已确认高保真设计的视觉差距。

**UI 优先：先核对设计、还原实际运行界面并经用户视觉验收，再集中保障功能与测试。** S002 已按其最小闭环范围验收关闭，不回写为失败，也不将该结项理解为稿件管理或完整 UI 已完成。用户指出的基础体验问题在 S003 独立记录、解决和验收。

技术路线继续保留完整 FigCraft 运行时。Agent 暂缓；未来 Agent 按云端接入 MCP 方向另立规格，本阶段不开发本地 Agent 产品入口、云端 MCP 服务、对话、模型或套餐。

## 已知基础与待核对的问题

当前实现基线为 S002 结项提交 `4b33c5bf`，应用实现为 `eedd960a`。以下为源码观察，不能代替运行验收或宣称已定位所有用户问题：

- 原生首页 `home.rs` 消费 `workspace_recents()`；后者读取既有最近路径列表并受 `MAX_RECENT` 限制（当前 20）。最近文件记录不能充当全部本地稿件目录。
- `workspace.rs` 的 New 调用现有 `file.new`，现有新建 / 保存 / 另存为是运行时文件流程；S003 需补清新建后落盘、首页可发现性和重启后的关系。
- `file.rename` 修改文档名，不直接重命名磁盘路径。不能用标签变化证明文件管理已完成。
- S002 已验证首页、标签、树和最小设计属性接入；仍需按本轮设计与实际运行逐项记录视觉差距，不能以功能接通替代还原。

源码入口：[原生首页](../../../apps/figcraft/src/native_workspace/home.rs)、[原生工作区](../../../apps/figcraft/src/native_workspace.rs)、[工作区动作与快照](../../../crates/ui-egui/src/workspace.rs)、[文件命令](../../../crates/engine/src/cmd/file.rs)、[文件对话框与保存](../../../crates/ui-egui/src/app/files.rs)。开发前逐项打开定义，确认复用范围和适配位置。

### 稿件与文件规则

以下为本规格的预期产品行为，尚未实现；I1 需给出与现有保存 / 恢复能力的映射，不能在开发中悄悄改变语义。

1. **应用内稿件**：使用持久、与名称及运行时 UID 无关的稿件标识，定位应用本地数据目录中的 `.figcraft` 内容；重启后重新绑定运行时 UID。名字可重复，内部文件地址不由用户名称拼接，不因重命名丢失身份。
2. **创建成功**：初始文件已可靠落盘且列表可发现，才视为创建完成。初始写入失败不留下幽灵记录或假成功界面；运行时已有内容保留并允许重试。连续新建的每份稿件相互独立。
3. **编辑与保存**：应用内稿件复用 FigCraft 自动保存 / 恢复机制；I1 明确实际触发条件、时间间隔、失败重试和 UI 保存状态映射。切首页、关稿与正常退出必须完成保存或给出明确可取消的处理，不能静默丢弃尚未落盘的修改。失败保留 dirty，不把恢复副本等同于主文件保存成功。
4. **列表来源**：本地目录 / 索引只记录定位与管理元信息，不复制可编辑文档、选区或撤销栈。应用内稿件目录与最近外部路径合并去重；最近上限不得隐藏老稿。默认按最近操作排序，名称搜索只过滤显示，不删记录；清空搜索恢复完整列表。
5. **命名**：应用内名称经原命令修改并保存，列表、标签、文件内名称一致；Enter 确认、Escape 取消，空白名拒绝，中文和长名正确处理。外部文件的“重命名”仅修改文档名称并在保存后写入内容，磁盘路径不自动改名；需要新路径时走明确的“另存为…”流程。菜单和亲验步骤必须表达这种区别。
6. **另存为**：沿用 FigCraft 的保存目标切换语义；外部新副本成功落盘后才更新路径 / 列表。应用内原稿继续作为独立已保存稿件保留；新路径作为独立文件登记，避免两个列表项错误共用同一运行时身份。I1 明确原稿与当前标签切换的时点，覆盖取消 / 冲突 / 失败，不另造导出格式或迁移旧数据。
7. **移除与删除**：外部文件仅提供“从列表移除”，不删除磁盘源文件；应用内稿件提供“移到废纸篓”，确认后使用可恢复的系统操作，不永久删除。未保存稿件先处理修改；取消保留全部状态。操作失败保持列表与标签，成功才移除记录并关目标标签。系统废纸篓能力需在实现前核对，不用直接 unlink 代替。
8. **失效与重复**：缺失 / 损坏 / 无权限文件不得打开成假空白稿；提供明确错误和移除失效记录的路径。重复打开同一路径复用原文档，不以显示名称匹配。列表刷新、搜索排序、异步保存和删除回调均捕获目标身份，不能按变化后的行号或当前标签执行。
9. **旧数据**：保留已有外部文件与最近记录；首次启用新管理方式不搬迁、不删除旧文件。不要求登录、不模拟云端稿件；任何元信息迁移需可重复执行且不重复登记。

## UI 来源、覆盖与验收边界

视觉来源沿用协作文件 `e37912c2dd7d1294` 的「Kodma · 高保真 UI」与「Kodma · Design System」。仓库可追溯来源见 [S002 设计对照](../002-native-workspace/design-reference.md)，但它是历史快照，**本轮尚未重新 live 核对**，不能声称 S003 已按最新设计逐项核实。

I1 在会话进入 live 后只读核对当前设计，记录页面 / 节点、尺寸、token 和缺失状态；凭据不入库。优先复用首页 `42949672961`、工作区共用布局 `42949673048` / `42949673135`、设计栏参考 `42949673295` 及组件规范。历史基线为 1440 × 960、左栏 242、顶部 84、右栏 408 逻辑尺寸；如 live 内容不同，先记录差异，再以用户确认的版本实现。

视觉阶段只做构建、启动、截图和必要的交互呈现；可复用现有真实数据或明确标明的合成夹具，不能用静态画板冒充产品截图。提供同尺寸设计 / 运行对照及逐项差异清单，经用户确认后进入功能保障。禁止用“差异已记录”替代解决范围内视觉问题。

Agent 输入、开始创作和任务模板的生成行为不在本轮；不把这些按钮改接为空白新建或生成模拟结果。I1 明确这些区域在当前无 Agent 版本中的隐藏 / 禁用与布局方案，作为视觉差异交用户确认；不要求还原不存在的业务。成员、分享和账户也不作为可用功能交付。控件能表达用途时不增加二级说明、口号或重复标题；必要的错误 / 删除确认仍应清晰。

## 技术约束

- 继续使用同一 Session / FigApp / UiState、NSWindow / WinitView / Metal、帧循环、渲染、后台调度、控制通道及撤销栈；不解耦、重写或创建第二份编辑模型。
- 稿件管理优先复用现有命令与平台服务；新用户行为通过命令体系，程序调用不直接弹窗。存储 I/O 与平台操作保持原分层及 WASM 可构建；不全局放宽 unsafe、修改 CI 或顺便升级底层依赖。
- 本地持久稿件标识与打开文档 UID 分离；任何异步回调在执行前重新校验归属。保存原子性、外部文件冲突和关闭确认复用既有保护；不得靠提前清 dirty 掩盖失败。
- 原生输入编辑、画布快捷键和菜单焦点继续互斥；保留中文预编辑交接。系统中文输入法由用户亲验，不标记为自动化通过。
- 新图标原创代码绘制；素材来源与许可符合仓库规则，新资产逐项登记 ATTRIBUTION。字体不入库，不复制第三方产品资产。
