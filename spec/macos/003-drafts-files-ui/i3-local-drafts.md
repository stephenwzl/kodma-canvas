# S003 I3：本地稿件创建、命名与保存

日期：2026-11-17。I2 整窗 UI 已由用户确认。I3 已接通创建 / 命名 / 本地保存及工程验证；完整 S003、I4 / I5 与系统中文仍未结项。

## 实现

原生宿主在启动时配置应用数据目录下的 Drafts。每份文件以 128 位随机标识定位为 <id>.figcraft，名称与路径分离；index.json 只保存标识、名称及已保存文件的变化戳，不存第二份可编辑模型。新建继续执行原 file.new，再通过原文件格式和原子写入保存；数据与索引均成功后才发布列表项。

引擎新增 draft.create / draft.list / draft.save 命令。桌面服务复用已有系统随机数能力生成标识，没有增加依赖；默认参考宿主和 Web 不配置本地管理目录。文件 I/O 沿用 file_access 的自动化访问约束。索引读取上限 4 MiB、最多 10000 条；目录枚举有界。启动时最多恢复 32 份缺索引或变化戳不一致的文件，超过上限明确失败，不静默截断或在 UI 帧解码全部稿件。

创建失败保留可编辑的内存稿及待写目标，不发布幽灵列表项。点击保存或再次新建会重试未完成的那份稿件。索引写入失败保持 dirty；文件已落盘而索引未提交的情况可在下次启动恢复。名称经去首尾空白后校验 1–256 字符；重命名不改变稿件标识。后台快照写回只把实际已保存的名称记入索引，后续尚未保存的名字仍在内存中。

受管稿件在停止修改约 3 秒后自动保存；失败沿用约 60 秒重试和显式保存入口，不修改全局偏好，不强制自动保存外部文件。版本检查点与崩溃恢复副本仍不是主文件保存证据。返回首页、关闭标签、正常退出前同步完成受管写入；失败则保留窗口 / 标签和 dirty，显示原错误。控制通道 app.quit 原先直接设置退出，已对受管稿件补同样的保存检查。

另存为先保存受管原稿，再沿用原系统选择器 / file.saveAs；目标写入成功后当前标签才变更路径。原稿继续在列表中，打开时获得独立运行时 UID。旧的后台快照检查 UID、路径与 saved_doc，不能把旧保存回调写入新目标。磁盘被外部修改时，仍使用原冲突保护。

受管列表来自索引，外部记录继续合并去重；不再用最近 20 条替代应用内目录。受管稿件暂不提供“从列表移除”，以免错误隐藏仍存在的应用内文件；真实系统废纸篓及完整管理流程在 I4 接入。

## 复现与亲验

用独立配置启动原生宿主：

```sh
KODMA_CANVAS_CONFIG_DIR=/tmp/kodma-s003-i3-review ./script/build_and_run.sh --workspace --verify --control 17995
```

点击一次新建，再运行 ruby script/verify_s003_i3.rb seed 17995，加入合成矩形 / 文字 / 渐变并等待真正自动保存。用原生菜单改名后运行 rename-record 阶段；save-as 阶段验证原稿与外部副本；fault 和 initial-fault 阶段仅允许命名明确的隔离 I3 配置，注入并恢复可逆故障。quit 阶段保存最后修改后退出；正常进程结束后用同一配置重新启动，再运行 restart 阶段，不能重新生成测试数据代替重启验证。

用户最短路径：新建 → 改内容 → 返回首页 → 改名 → 关闭 / 重新打开 → 正常退出 / 重启 → 核对最后内容。系统中文输入法和完整 S003 亲验留待用户；I4 的废纸篓、失效记录与更完整列表管理、I5 的综合回归仍按原规格推进。
