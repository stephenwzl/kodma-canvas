# S001：保留 FigCraft 运行时的画布显示与原生承载

更新日期：2026-11-16。修订：v2。状态：已完成。2026-11-16 用户确认验收通过；跨不同显示比例测试按用户决定取消。

## 目标与路线

保留完整 FigCraft 编辑器运行时，通过 UI 显示策略隐藏其首页、标签条、工具栏和外围侧栏，使画布填满宿主提供的区域，并随窗口或区域尺寸变化。在此基础上验证 SwiftUI / AppKit 窗口承载现有 egui 视图的可行性。

首要约束是尽量保持跟进 FigCraft 升级的兼容性：复用上游的状态、帧循环、输入、渲染和命令处理，减少长期分叉。继续使用完整 FigApp / UiState 是本路线的明确选择，不以结构解耦为完成条件。隐藏外围 UI 后，原有功能逻辑仍保留。

当前已验证保留 winit 窗口和内容视图的 AppKit 同窗组合，承载范围和限制见[实现说明](implementation.md)。仅隐藏 UI、调整独立窗口大小，不等于已将画布嵌入原生窗口；S001 必须分别给出仅画布显示和原生承载的运行证据。进度见[迭代记录](progress.md)，亲自验收见[测试稿与 case](acceptance.md)。

## 范围与兼容约束

本阶段包含：

- 提供可重复启动的仅画布模式，同时保留默认 FigCraft 参考编辑器；显示策略属于宿主配置，不写成稿件内容或改变稿件格式。
- 在现有 UI 路径上控制外围元素是否绘制，保留必要的编辑覆盖层、手柄、右键编辑操作和错误反馈。
- 画布布局随宿主区域大小与位置、窗口变化和显示比例更新，沿用既有视口及命中坐标处理。
- 用最小 macOS 原生验证宿主承载现有 egui 内容视图，验证事件循环、GPU 显示、焦点、中文输入和资源生命周期。原生测试控件仅用于验证区域与焦点变化，不在本阶段实现产品页面。
- 复用现有 MCP attached / 控制通道，验证命令作用于可见画布的同一份文档；保持隐藏或非前台状态下的后台处理。
- 对改动点做回归，并记录与所选 FigCraft 基线的差异及升级演练结果。

具体实现遵守以下约束：

1. 不拆分 Session、FigApp、UiState，不重写渲染器、工具、撤销、协作或 MCP；不为仅画布模式复制整套帧循环和输入处理。
2. 优先复用已有 UI 可见性及布局能力；仅补足隐藏策略和宿主适配所需的局部改动。不能只依赖用户可随时切回的“隐藏 UI”状态，导致 Kodma 模式意外重新露出上游导航。
3. 隐藏面板不销毁其状态，不停用命令、协作、保存或异步任务；特殊编辑状态不以面板是否绘制为由被清空。检查依赖面板绘制才能完成的逻辑并记录，必要时做最小适配。
4. 原生桥接集中在宿主适配层，不为桥接全局放松安全检查，不顺便升级 egui / winit，不改变现有 WASM 构建和默认参考编辑器行为。
5. 每次本地适配能说明其目的、涉及的上游位置、对应回归场景及升级时的核对点。不以“零冲突”或“以后自动兼容”作为未经验证的承诺。

本阶段不实现 Kodma 首页、完整原生导航和右栏、账户、云端名额、付费模型或套餐服务。多稿件、协作、成员跟随、分享权限及 MCP 继续复用原实现；双稿件、双客户端的完整产品回归留在工作区接入阶段，不作为开始本阶段的前置项目。

## 源码起点与职责

本轮从已推送的 `0ae737f1` 开始；其应用源码仍为既有 FigCraft 基线。以下位置需要核对和尽量保持原样：

| 现有位置 | 保留职责及核对点 |
| --- | --- |
| [FigApp / UiState](../../crates/ui-egui/src/lib.rs) | 保持完整状态及文档归属，由原有运行时管理 |
| [UI 帧循环](../../crates/ui-egui/src/app.rs)及[帧处理](../../crates/ui-egui/src/app/frame.rs) | 保留调用顺序，仅控制外围 UI 的显示与画布区域 |
| [canvas::show](../../crates/ui-egui/src/canvas.rs) | 继续使用现有画布、覆盖层、输入和渲染路径 |
| [background_tick](../../crates/ui-egui/src/app/commands.rs) | 保留控制请求、协作轮询、异步完成和保存调度 |
| [桌面入口](../../apps/figcraft/src/main.rs)与[Services](../../crates/ui-egui/src/services.rs) | 验证窗口与视图适配、事件循环、平台服务及关闭行为 |
| [MCP backend](../../crates/mcp/src/backend.rs)与[控制协议](../../docs/control-protocol.md) | 继续连接同一运行时，不另外启动 headless Session |

Kodma 原生宿主负责提供画布区域、转交焦点与平台事件、管理视图生命周期。完整 FigCraft 运行时负责编辑和调度。原生侧只读取显示所需信息，不维护第二套可编辑文档。

## 原生承载验证

先确认当前固定版本的 eframe / winit 内容视图、事件循环与 AppKit 的所有权，再确定最小适配方式。不能预设把现有顶层窗口改大小、搬动或遮住边缘即可得到可靠的原生子视图。

验证必须覆盖原生窗口中实际承载的 egui 画布，并记录内容视图、图层或 surface 的创建与销毁、显示比例和焦点交接。如果现有承载方式不可行，记录具体限制并修订宿主方案；不自行恢复编辑器大拆分，也不以独立窗口或图像预览替代原生嵌入验收。

## 验收场景

使用同一套合成稿件对照同版本默认 FigCraft；先检查仅画布模式，再在原生验证宿主重复受承载影响的场景。保留必要编辑反馈，不增加说明标签或口号。

| 编号 | 操作 | 预期结果与证据 |
| --- | --- | --- |
| AC01 | 分别启动默认编辑器与仅画布模式；选择对象、切工具、打开或切换稿件 | 默认界面保留；仅画布模式不出现上游首页、标签条、工具栏及外围侧栏；隐藏策略不改写稿件，必要编辑覆盖层可用；记录启动方式与截图 |
| AC02 | 在 macOS 原生窗口中承载画布，改变原生侧区域宽度、位置和窗口大小（跨不同显示比例测试已由用户取消） | 画布占据正确区域；光标、命中、选区与渲染坐标一致，无裁切错位；记录真实嵌入截图与承载方式，独立窗口不计通过 |
| AC03 | 创建形状、选择、多选、框选、拖动、调整尺寸和旋转，平移缩放；检查已有特殊编辑状态 | 基本工具与覆盖层表现和默认编辑器一致；隐藏面板不清空渐变、裁剪、原型等状态，发现的入口或绘制依赖逐项记录并处理 |
| AC04 | 使用系统中文输入法组词、取消和替换文本；在原生输入控件与画布间切换焦点 | 无丢字、重复提交或输入串到另一处；候选框定位正确，原生输入时不触发画布快捷键；需 macOS 实机检查 |
| AC05 | 人工编辑与外部命令交替操作，逐步撤销重做；复制粘贴、拖放与文件操作 | 保持既有事务及平台服务语义；一次手势不重复提交，外部命令不被误并入手势，取消对话框不破坏编辑状态 |
| AC06 | 经控制通道和 MCP attached 读取、创建及修改对象，随后用鼠标编辑 | 操作同一运行时、同一文档并正确重绘；无效目标与非法命令返回既有错误；截图与输入接口对应实际承载的视图 |
| AC07 | 隐藏、最小化或切出画布后提交命令，恢复显示；驱动已有协作与异步结果处理 | 后台调度继续处理，恢复后显示最新状态；记录隐藏方式与结果，区分应用隐藏和系统休眠，不因不绘制面板而停用任务 |
| AC08 | 多次创建和关闭原生承载视图、恢复显示、改变区域尺寸；对照默认编辑器性能并运行适用质量检查 | 文档与资源生命周期正确，无旧渲染结果覆盖、重复事件处理或持续资源增长；记录输入响应、渲染延迟、CPU、内存和检查结果 |
| AC09 | 审查全部适配差异，选择明确的后续 FigCraft 提交或版本做本地升级演练 | 核对 UI 显示策略、原生承载接口、帧调度与构建；记录演练基线、目标版本、冲突及重跑结果。未演练只标为待验证，不宣称升级兼容已通过 |

AC09 以本地演练验证维护成本，不自动发布或替换项目基线。版本选择以实施时的实际代码为准，不为追新扩大改动范围。
